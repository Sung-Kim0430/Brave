# 代码修复计划

生成时间: 2026-06-08

## 第一轮发现的问题

### 高优先级（安全/逻辑错误）

1. **post.php & index.php - 缺少 App 类加载**
   - 文件: `post.php:3`, `index.php:13`
   - 问题: 使用 App 类但未检查/加载
   - 修复: 添加与其他模板文件相同的类加载逻辑
   - 影响: 如果模板直接访问可能导致致命错误

2. **base/main.js:451 - 正则表达式转义错误**
   - 文件: `base/main.js:451`
   - 问题: `\\.(png|...)` 双重转义，在JS字符串中应为单反斜杠
   - 修复: 改为 `/\.(png|jpe?g|gif|webp|svg)(\?.*)?$/i`
   - 影响: 图片链接lightbox可能不工作

### 中优先级（代码质量）

3. **App.php:159 - 不必要的 stripcslashes**
   - 文件: `core/App.php:159-163`
   - 问题: `stripcslashes()` 在正则提取的属性值上调用是多余的
   - 修复: 直接使用提取的值，无需反转义
   - 影响: 可能导致意外的反转义行为

4. **functions.php - 中文字段名**
   - 文件: `functions.php:312-319`
   - 问题: 使用中文作为字段名（`头部自定义`、`Css自定义`等）
   - 修复: 保持向后兼容，但标注为遗留代码
   - 影响: 代码可读性和维护性

### 低优先级（过度防御）

5. **App.php:492-495 - DOMDocument 检查过度防御**
   - 文件: `core/App.php:492-495`
   - 问题: 现代PHP环境中DOMDocument总是存在
   - 修复: 移除检查或添加注释说明这是极端情况的回退
   - 影响: 无实际影响，仅代码清晰度

6. **App.php 中的多个防御性检查**
   - 各种 `is_string()` 检查后立即转换为 string
   - 建议: 简化为直接类型转换（PHP会处理）

## 修复顺序

1. 修复 post.php 和 index.php 的 App 类加载
2. 修复 base/main.js 的正则表达式
3. 简化 App.php 中的 stripcslashes 调用
4. 标注中文字段名为遗留代码（不改动以保持向后兼容）
5. 简化过度防御的代码
